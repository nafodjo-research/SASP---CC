## Specific Evaluations (as requested)

### F04 `clustered_ct()` — correctly built but under-used
The helper properly wraps `sandwich::vcovCL(mod, cluster = cl, type = "HC1")` inside `tryCatch`, falls back to naive SE if clustering fails, and re-normalizes column names before table generation. It is CORRECT.

**But** the end-of-script summary block (F04 lines 758–772) bypasses it: it re-extracts p-values from `coef(summary(mod))`, which reports the naive z. The summary text will contradict the tables. Fix: call `clustered_ct(mod, res$data)` in the summary loop.

Additional concern: with match-level observations nested in (player_id, tourney_id_event), single-way clustering at `player_id` may under-cluster within-event correlation. Two-way clustering at (player_id, tourney_id_event) via `sandwich::vcovCL(cluster = ~ player_id + tourney_id_event)` would be more defensible.

### F11 extended BH (80 tests) — defensible, but not correlation-aware
The family 4 outcomes × 4 samples × 5 horizons = 80 is a legitimate joint-family definition. `p.adjust(method="BH")` is applied at that level AND within-outcome (`qval_within`) — good.

**Concerns:**
- BH is conservative but valid under positive regression dependency, which is likely for correlated outcomes.
- Romano-Wolf stepdown is the recommended correlation-aware alternative.
- The family definition should be stated explicitly in the paper's methods section.

### F14 classification logic — subtle bug
The rule `rank_among_losers > 1` implicitly assumes `n_ll_slots == 1`. Under the ranking rule with K slots, the top K losers are picked deterministically. So:
- If n_ll_slots = 2 and rank_among_losers = 2, the entry could STILL be deterministic (2nd post-qualifying withdrawal).
- The mathematically correct rule is `rank_among_losers > n_ll_slots`.

Empirically the impact is small: F14d's news audit found 0/23 rank-1 ambiguous entries were lottery. But the fix is one-line: `treated$rank_among_losers > treated$n_ll_slots`.

### F14c event-level verified-lottery rule — mostly correct
Multi-slot events are handled: any treated LL with rank > 1 at an event makes the whole event verified-lottery, so co-treated LLs (even the rank-1 one) enter the sample. The docstring correctly notes this is looser than F13's "ALL treated must have rank > 1" rule.

**Note:** F13 uses `group_by(tourney_id)` without adding tour or year. If a Sackmann `tourney_id` is not fully unique across tour × year, this pools events. F14c supersedes it correctly, but F13's stale outputs still ship the older `table_verified_firstll.tex`.

### F15 mechanical decomposition SE — conservative but defensible
The delta-method formula `sqrt(sum(w^2 * se^2))` treats the stratum-specific betas as independent random variables. Since the strata are disjoint, the independence assumption is defensible for the point estimates.

Missed detail: players can reappear across strata over time. Since each regression clusters at `player_id` within its own slice, the within-stratum SE handles this, but a formally correct joint SE would need a block-bootstrap resample at the player level.

### F14d tribble structure — join is exact-match
Join key is (tour, year, player_name). Player names can drift across data sources (accents, hyphens). The script correctly emits `WARNING` when a tribble row doesn't join, but **does not fail hard**.

Fix: `stopifnot(updated_rows == nrow(news_updates))` at line 161.
